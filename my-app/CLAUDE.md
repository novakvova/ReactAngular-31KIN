# CLAUDE.md

Інструкції для Claude Code у проєкті `my-app`. Читати перед будь-якою зміною коду.

## Про проєкт

- React-застосунок на **Create React App** (`react-scripts 5.0.1`), мова — **JavaScript** (не TypeScript).
- Навчальний проєкт курсу «React / Angular» (Kodedj, 2025-2026). Поточний стан — стартовий шаблон з одним заголовком.
- Специфікація: [spec.md](spec.md). Змінюючи поведінку застосунку, оновлюй spec.md.

## Команди

Виконувати в папці `my-app`:

| Команда | Призначення |
|---|---|
| `npm start` | Запуск dev-сервера на http://localhost:3000 |
| `npm run build` | Production-збірка в `build/` (має проходити без помилок) |
| `npm test` | Тести у watch-режимі. Для одноразового запуску: `npm test -- --watchAll=false` |

Залежності встановлюються через `npm install`. Не додавай нові бібліотеки без погодження з користувачем.

## Структура

```
my-app/
├── public/            index.html, manifest.json, favicon, robots.txt
├── src/
│   ├── index.js       точка входу: ReactDOM.createRoot, імпорт стилів, <App />
│   ├── App.js         кореневий компонент (зараз — заглушка)
│   ├── App.css        стилі App (CRA-шаблон)
│   ├── index.css      глобальні стилі
│   ├── custom.scss    SCSS: перевизначення змінних Bootstrap ($body-bg) + імпорт bootstrap
│   ├── App.test.js    тест CRA-шаблону (див. «Відомі проблеми»)
│   ├── setupTests.js  налаштування Jest / @testing-library/jest-dom
│   └── reportWebVitals.js
├── package.json
└── README.md          стандартний README CRA
```

Нові компоненти — у `src/components/` (кожен у своєму файлі `Назва.jsx` або `Назва.js`). Сторінки маршрутів — у `src/pages/`. Не розкидай код по корені `src/`.

## Стек (з package.json)

- **react** / **react-dom** `^19`, `createRoot`
- **react-router** `^8` — маршрутизація (BrowserRouter / Routes / Route / Link)
- **bootstrap** `^5.3` + **sass** — стилі; Bootstrap підключається через `src/custom.scss`
- **@testing-library/react**, **@testing-library/jest-dom**, **@testing-library/user-event** — тести
- **web-vitals** — метрики (через `reportWebVitals.js`, зараз не використовується)

## Правила коду

- Функціональні компоненти з хуками. Без class-компонентів.
- Один компонент за файлом; експорт — `export default`.
- Весь текст інтерфейсу — **українською**. Назви змінних, функцій, файлів і коміти — англійською.
- Стилізація: спочатку класи Bootstrap, власні стилі — мінімально. Нові SCSS-правила додавай у `custom.scss` або CSS-файл поруч із компонентом.
- Посилання всередині застосунку — `Link` з react-router, а не `<a href>`.
- Не залишай `console.log` у коді, який комітиш.
- Секрети, токени, паролі, URL приватних API — не в репозиторії; використовуй `.env.local` (він у `.gitignore`).

## Git

- Git-репозиторій знаходиться в батьківській папці `1.React Angular`, а не в `my-app`. Шляхи в `git status` відносні до неї.
- Комітити лише зміни всередині `my-app/`, якщо користувач не попросив інше.
- **Не чіпати** інші папки й файли репозиторію: `my-auto`, `test-client`, `vite-qrcode` та файли в батьківській папці (`HomeWork*.txt`, `Теми занять.txt`).
- Не коміти `node_modules/`, `build/`, `.idea/` (див. «Відомі проблеми»).
- Стиль повідомлень коміту — короткий англійський опис, як у історії: `Add routes`, `Add libs`.

## Відомі проблеми

1. **`src/App.test.js` застарів.** Він шукає текст «learn react», якого немає в `App.js`, тому тест падає. Перед змінами в App оновлюй тест або видаляй його разом із погодженням з користувачем.
2. **`.idea/` не в `.gitignore`.** Файли IDE потрапляють у `git status`. Не додавай їх у коміти.
3. **`src/custom.scss` частково в індексі git** (статус `AM`). Перед комітом перевір, що в коміті є саме потрібна версія файлу.
4. **Імпорт `~bootstrap/...` у `custom.scss`.** Синтаксис `~` — застарілий для Sass. Якщо збірка показує попередження, заміни на `@use 'bootstrap/scss/bootstrap'` із `loadPaths`, але тільки після підтвердження.

## Перевірка змін

Перед тим як сказати, що зміна готова:
1. `npm run build` завершується без помилок.
2. Для логіки з тестами — `npm test -- --watchAll=false` (з урахуванням пункту 1 вище).
3. Для UI — запусти `npm start` і перевір сторінку у браузері, якщо можливо.

Якщо щось не вдається перевірити — скажи про це прямо.
